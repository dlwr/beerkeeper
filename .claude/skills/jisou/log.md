# 自走ログ

回ごとの経過は書かない（PR は git 履歴で追える）。200 行以内に保つ。

## もう出さない候補

- 終了後の参加・キャンセル: 終了したイベントでは受け付けないと決めた（#68）。開催中は許す
- テキストメールの HTML エスケープ: `text/plain` のテンプレートはエスケープされず、`&` はそのまま届く（確かめ済み）

## 測って分かった前提

- RunSpecs は 1 分ほどで終わる
- 本番 DB は Fly ボリューム上の SQLite で、マイグレーションはマシン起動時の `db:prepare` で流れる。デプロイが失敗するとマイグレーションだけ流れた状態にはならないが、戻すにはボリュームの復元が要る

## 踏んだ罠

- クラウドの初期イメージには `.ruby-version` の Ruby が無く、`/opt/node22/bin` に Chrome と版の合わない chromedriver がある。環境の setup で `bin/cloud-setup` が片付ける。`ruby -v` が違えば `bash bin/cloud-setup` を流して `. /etc/profile.d/ruby.sh` する
- system spec の Chrome はパスワード漏えい検知のダイアログで次のテストの送信を止める。`spec/support/capybara.rb` で `profile.password_manager_leak_detection` を切ってある
- クラウドのセッションでは、ダウンロードした外部バイナリ（Litestream など）の実行が権限で拒否されることがある。オーナーが許可すれば動く（flyctl は `fly.io/install.sh` で入った）。ただし Fly のトークンは環境に無く、`fly secrets list` などは使えない
- 1 つの作業ブランチで PR を続けて出すと、squash マージ済みの古いコミットがリモートに残って push が弾かれる。force push はせず、リモートのブランチをマージしてから push する
- rspec を流すと `app/assets/builds` が消えることがある。開発サーバーで画面を見る前に `bin/rails dartsass:build` する
- PR 本文に `Closes` を2つ並べると片方しか閉じないことがある。マージ後に issue の状態を確かめる
- CI とクラウドの test DB にはシード（`mitakarb` のイベントなど）が入っている。全件を数える・並べるテストは自分で作った行に絞る
- PR 本文の `Generated by` フッターは、REST で消してもサーバー側で付け直される
- `gh api search/issues` は `is:issue` か `is:pr` を q に入れないと 422 になる
- ログインが要るコントローラーには `before_action :require_login` を自分で付ける。`authenticate` は `current_user` を入れるだけ
- 作業ブランチは1本なので、PR の CI 待ちの間に次の issue は `wip-*` のローカルブランチでコミットし、マージ後に main を取り込んでから cherry-pick して push する。リモートのブランチ削除はプロキシで拒否される
- `bin/cloud-setup` の `db:setup` が test DB の外部キーで落ちることがある。`RAILS_ENV=test bin/rails db:drop db:create db:schema:load` で作り直せば rspec は通る
- `bundle exec` が見つからないときは `. /etc/profile.d/ruby.sh` を同じコマンドの中で読む（シェルの状態は呼び出しごとに消える）
- steep の `lenient` は未定義メソッドを見逃す。`Steepfile` は `default` にしてある。手書きの型は `sig/app/`、生成物は `sig/rbs_rails/`（モデルや関連を変えたら `bin/rails rbs_rails:all`）
- `rbs_rails` は開発 DB が migrate 済みでないと失敗する。開発 DB を migrate すると `db/schema.rb` の列順が崩れることがあるので、`db:drop db:create db:schema:load` してから migrate し直す
- steep は `has_many` のスコープの lambda の self を自クラスとみなす。別クラスのスコープを呼ばず `where(...)` で書く（クラス起点にすると join 時の別名に追従しない）。concern の `included do` も型が付かないので、関連はモデルに直接書く
- 本番の挙動は `SECRET_KEY_BASE_DUMMY=1 RAILS_ENV=production bin/rails runner ...` で手元でも見られる（DB には触らない範囲で）
- `participation` の factory は `user` を作らない。`create(:participation, event:)` だけだと検証で落ちるので `user:` を渡す
- `event_cancellation` の factory は存在しないクラスを指していて使えない。中止は `event.cancel` で作る
- request spec でページの一部だけを確かめるときは見出しで区切る（イベント名に「中止」などの語が入ると本文全体の include では区別できない）。`travel_to` の中で遅延の `let` を初めて呼ぶと、作成日時もずれる
- 否定の matcher（`define_negated_matcher` で作ったもの）に `.with` は付けられない。`not_to have_enqueued_mail(...).with(...)` と書く
- `rbs_rails:all` は触っていないモデルの生成物も列順を変えて書き直す。変えたモデルの分だけ残し、ほかは `git checkout` で戻す
- squash マージ後に main を作業ブランチへ取り込むと、新しく足したファイルが add/add で衝突する。中身は作業ブランチの方が新しいので `git checkout --ours` で解く
- 本番の DB を試すときは `RAILS_STORAGE_PATH` に一時ディレクトリを渡すと、`storage/` を汚さずに `db:prepare` まで流せる（`spec/scripts/production_queue_spec.rb`）
- Discord の HTTP は WebMock でスタブする。シークレットは `:discord` タグ（`spec/support/discord.rb`）で入れ、ほかの ENV は `with_env` で一時的に変える
- request spec のログインは `log_in(user)`（`spec/support/login.rb`）で、スタブした Discord の OAuth を通す。system spec は `allow_any_instance_of(ApplicationController).to receive(:current_user)`
- パスワードのログインが無いので、開発サーバーでは Discord のシークレット無しにログインできない。画面の点検は、`ApplicationController#authenticate` をクッキーの `dev_user_id` で差し替えるスクリプトを scratchpad に置き、`RUBYOPT=-r<それ> bin/rails s` で起こして Playwright で撮る（`ActiveSupport.on_load(:after_initialize)` で prepend する）
- `gh pr create --attach` と `gh pr comment --attach` は GraphQL を通るので、クラウドでは 403 で使えない（gh 2.103 でも同じ）。スクリーンショットの添付はやめ、判定できることは spec に、見た目は本番の URL を報告に並べる
- 点検用のログイン差し替えは `ActiveSupport.on_load(:after_initialize)` だけだと、app/ のファイルを変えて再読み込みされた時点で外れる。`Rails.application.reloader.to_prepare` の中で prepend する。スクリプトの先頭で `require "active_support/lazy_load_hooks"` も要る
- 開発 DB が空（テーブル無し）のことがある。`bin/rails db:drop db:create db:schema:load db:seed` で作り直す
- UI の方針は `design.md`。色・余白・部品は `app/assets/stylesheets/application.bootstrap.scss` の変数とクラスにまとめてあり、画面ごとに新しい値を足さない
- 詳細画面の項目は `dl.event-facts` の dt/dd。request spec は `event_fact('参加人数')`（`spec/support/event_facts.rb`）で値を取る
- 横スクロールとタップ範囲は `spec/system/layout_spec.rb`（`spec/support/layout_checks.rb` の `resize_viewport`・`horizontal_overflow`・`small_tap_targets`）で確かめる。新しい画面や状態はここに足す。キーボードの Tab 順とフォーカスの輪郭は手元で確かめ済み（spec にはしていない）
- `field_error_proc` は素通しにしてある。欄のエラーは `field_error_attributes` と `field_error`（`EventsHelper`）で `aria-invalid`・`aria-describedby` と欄の下の文言を付ける
- CI の Chrome は手元と書体が違い、インラインの要素の高さが 3px ほど低く出る。44px の判定は手元でぎりぎりにしない（本文中のリンクは `.text-link` の上下の余白で取っている）
- 開発サーバーの点検用ログイン差し替えは、`to_prepare` に登録するだけだと起動直後のリクエストに効かない。`on_load(:after_initialize)` の中で一度 prepend してから `to_prepare` にも登録する
- 画面の点検は scratchpad に axe-core（`npm i axe-core`）を入れ、Playwright で各画面に注入して流すと早い。2026-11 時点で全画面の違反は 0
- DM の文面の spec で「含まない」を確かめる語は、定型文（「ください」「さん」など）に入らない文字にする
- 印や状態の有無を確かめる spec は部品（`.seat-status` など）に絞る。テストのイベント名（「今日の会」）に同じ語が入っていると、行の文字全体では否定も肯定も誤って通る
- 利用者の入力をリンクにするのは `text_with_links` / `format_with_links`（`EventsHelper`）。`simple_format` に直接渡さない
- 手元の test DB では `spec/requests/events_request_spec.rb` の一覧の3件（:14, :27, :67）が main でも落ちる（2026-11-21 時点。CI は緑）。シードの過去のイベントで最近の5件から押し出されるためとみられる
- 別の issue を wip ブランチで並行するときは、同じブランチに意味単位でコミットして後で cherry-pick する。`git checkout <branch> -- .` で持ち出すのは auto mode に拒否される
- `content_for` の値を `join` すると二重にエスケープされる。`safe_join` を使う
- `bin/rails runner '...'` に日本語を直接書くと、ロケールが POSIX のクラウドでは文字列が BINARY になり `Encoding::CompatibilityError` で落ちる。`LANG=C.UTF-8` を付ける
- 一覧の部分テンプレート（`events/_list`）のイベント名は既定で h3。h1 の直下に並べる画面では `heading: :h2` を渡す（#169）
- 終了したイベントは `cancel` が何もしない（#173）。過去の中止イベントが要る spec は `travel_to(event.start_at - 1.day) { event.cancel }` で作る
- Chrome 158 では Capybara 3.40 の `reset!` が送る `Storage.clearDataForOrigin`（`origin: '*'`）が拒否され、system spec が全件 `invalid argument: * is not a valid URL` で落ちる。`spec/support/capybara.rb` でテストサーバーの origin に置き換えてある（#184）。Capybara を上げて直っていれば外す

## 残っている候補

- 開発環境で Discord 無しにログインする手段（development だけのログイン）。今は点検用のスクリプト頼み。ログイン画面の説明も Discord のシークレットが無いと表示されず、見た目を確かめられていない
- `max_size` に DB の CHECK 制約が無い（検証はモデルだけ）。本番に 0 以下の定員が残っていないかも未確認
- 一覧の満席の色（`seats_full?`）と文言（`seats_status`）が別の判定。片方を変えるとずれる
- 主催者は自分のイベントにも「参加する」で参加でき、定員に数えられる。主催者は参加するものとみなして変えていない。主催者を自動で参加者にするかは未決
- URL のリンク化（#140）は詳細画面だけ。DM・マイページと、`www.` だけの URL・メールアドレスはリンクにならない
- 一覧の自分の参加状態（#141）は開催予定だけ。過去のイベントに「参加した」は出さない
- 過去のイベントの画面（#146、`/events/past`）は 20 件ずつのページ送りだけで、検索・年ごとの絞り込みは無い。ページ番号は 10000 で頭打ち
- 「今日」「開催中」の印（#147、#151）は一覧・詳細・マイページの開催予定の行だけ。DM には出さない。中止の判定は詳細のビューで行い、一覧は `not_cancelled` で絞った前提（ヘルパーで `cancelled?` を見ると一覧で N+1 になる）

- 型検査は `app/models` だけ。コントローラー・コンポーネントへ広げるのは次の候補
- `users#destroy` は画面から呼べないうえ、参加が `dependent: :nullify`（`user_id` は NOT NULL）、主催イベントの参加が `restrict_with_error` で実際には消せない（参加者のいるイベントの主催者だと `RecordNotDestroyed` で 500 になるはず。未確認）。退会を作るなら仕様から
- セッションはクッキーに `user_id` を持つだけなので、ほかの端末のログインを切る手段が無い

- 参加できなかった理由（#152）はコントローラーで参加済み・終了・中止を見直して出す。`Event#receive` は今も `nil` を返すだけで、それ以外の検証エラーは「参加できませんでした」のまま
- `Event.upcoming` / `.past` は `end_at` で分けるが、DB は `end_at` の NULL を許すので、NULL の行はどちらにも出ない（モデルでは必須）
- `ErrorNotifier` の間引きは `Rails.cache`（本番は既定のファイルストア）頼み。マシンが複数台になると台ごとに1通ずつ届く
- Litestream のコンテナは linux-x86_64 固定。arm64 の Mac で `docker compose build` すると使えないバイナリが入る（`BUCKET_NAME` が無ければ呼ばれない）
- .ics（#74）は `SEQUENCE` を出さない。日時変更後に取り込み直したとき、上書きされるかはカレンダーアプリ次第。中止理由も入れていない
- 参加費（`budget`）は文字列の列。詳細では数字だけなら「円」を付ける（#82）。一覧には開催場所と参加人数・満席を出す（#87）が、参加費は出していない
- 本番の Active Job は Solid Queue（Puma 内の async モード、`storage/production_queue.sqlite3`）。止まる瞬間に送信中だったジョブは次の起動で再実行され、DM が2通になりうる。`min_machines_running = 0` なので、時刻指定のジョブ（429 の再試行）はマシンが起きるまで走らない。キューの DB は Litestream の対象外。歓迎の DM の失敗は今も `Rails.cache`（ファイルストア）頼み
- 開催前日のリマインドは、Solid Queue の recurring で作れるが、マシンが止まっていると時刻どおりに走らない
- 歓迎の DM を積むところで例外が出るとログインは 500 になり、次のログインでは新規ではないので歓迎の DM は二度と送られない（async では起きにくい）
- イベントをもとにした新規作成（#90）は内容を写すだけで、日時は空。翌月の同じ曜日などを入れる案や、繰り返しイベントは未着手
- `<title>` は `page_title`（`ApplicationHelper`）で画面ごとに付ける。区切りはエラーページに合わせて全角の「｜」。新しい画面を足したら呼ぶ
- OGP（#157）はイベント詳細だけで、`og:image` は無い。Discord での実際の見え方は未確認
- 終了日を省けるのは日付だけ（#158）。開始日を JavaScript で終了日に写すことはしていない
- フォームの欄はイベント名が先頭（#163）。順は `spec/requests/events/form_request_spec.rb` で確かめている。欄を足したら期待の並びも直す
- マイページの行の場所（#164）は文字だけでリンクにしない。残りの枠は出していない
- DM の日時は変更前後の行も詳細画面と同じ表記（#168）。変更前後の終了日時は、日をまたがなくても日付を付けて出す
- 終了したイベントの詳細ではカレンダーに追加のボタンを2つとも出さない（#174）。中止かつ終了でも .ics のリンクは出ない（URL は直接開ける）
- マイページの過去の一覧は最近の5件（#179）で、残りは `/events/past` へのリンクだけ。自分が関わったイベントだけの過去の画面は無い
- 参加・補欠登録のフラッシュは DM でも知らせると伝える（#178）。DM が送れない人にも同じ文言が出る（歓迎の DM の失敗は別の警告で出す）
- マイページの主催するイベントの行には参加人数と残りの枠を出す（#183）。参加予定の行には出さず、補欠の人数も出さない
- 作成画面の見出しと送信ボタンは「イベントを作成」、編集画面は「〇〇を編集」と「変更を保存」（#186）。名前の編集画面の送信ボタンは「保存」のまま
- 参加登録・繰り上げの DM に参加者へのお知らせを載せる（#187）。送る時点の `participant_notice_visible_to?` で判定し、1000 文字で切る。お知らせを編集しても DM は送らない。名前・場所が長いと DM 全体が 2000 文字を超えて届かないことがある（全体の切り詰めは無い）
- 編集画面と更新後のフラッシュで、日時・場所の変更を DM で知らせる人数を出す（#191）。数は補欠を含む参加の件数で、DM が届かない人も数える
